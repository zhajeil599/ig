支付栏目新增用户手续费配置

需求方：自来也（PHP）· 2026-11-08
目标
支付宝、微信这类在线充值通道成本高。商户可对指定支付栏目向用户加收手续费，引导用户改用钱包充值。订单金额、到账金额、用户累计充值等原有口径都不变，只在订单上新增「手续费」和「实际支付金额」。

一、后台配置（支付栏目新增 / 修改）

  1. 新增「用户手续费」，三选一：不收取（默认）/ 固定金额 / 百分比。
  2. 固定金额：每笔订单收取固定金额，单位元，大于 0，最多两位小数。
  3. 百分比：按充值金额的比例收取，大于 0 且不超过 100，最多两位小数。
  4. 适用范围：除银商充值类外，所有支付栏目都显示该配置。系统不区分人民币通道和钱包通道，所以虚拟币钱包这类栏目也能配置，商户一般不配。
  5. 银商充值类栏目不显示该配置（不生成充值订单）。
  6. 内嵌钱包不在支付栏目中配置，不支持手续费，本需求不改动。
  7. 固定金额渠道提醒：有的支付渠道只收几个固定金额（如只收 300）。栏目开启手续费后，用户选 300 实际要付 306，这类渠道收不了。保存栏目时，若开启了手续费且该栏目下有只收固定金额的渠道，弹窗提醒「该栏目下有固定金额渠道：xxx。开启手续费后，这些渠道将无法匹配，用户可能看到暂无可用通道。」，可选择「返回修改」或「仍然保存」。
  8. 修改后只对之后新发起的订单生效，已生成的订单不变。
  9. 支付栏目列表新增「用户手续费」列：不收取显示「—」，固定金额显示「2.00 元/笔」，百分比显示「2%」，银商充值类栏目显示「不支持」。
  10. 后台统一叫「用户手续费」，与托管支付订单里的托管平台手续费区分。

二、计算规则

  1. 手续费 = 固定金额；或 = 充值金额 × 百分比，四舍五入到分。
  2. 实际支付金额 = 充值金额 + 手续费；向三方发起支付时按实际支付金额下单，支付渠道也按实际支付金额匹配。
  3. 虚拟币/钱包类栏目配置后，对该栏目下所有支付渠道生效。
  4. 单笔上下限、固定金额按钮的判断仍按充值金额。
  5. 赠送金额仍按「充值金额 × 真实优惠比例」计算，不含手续费。
  6. 三方回调的支付金额与实际支付金额不一致时，沿用现有处理方式。
例 1：百分比 2%
充值 100.00 → 手续费 2.00
实际支付 102.00，到账 100.00
例 2：固定 2 元/笔
充值 50.00 → 手续费 2.00
实际支付 52.00，到账 50.00

三、订单与统计口径

  1. 订单金额、到账金额都等于充值金额，不变；订单新增「手续费」「实际支付金额」。
  2. 用户累计充值、首充判断、VIP 等级、充值稽核打码量、报表里的充值总额，都按充值金额，不受手续费影响。
  3. 不收手续费的订单（含历史订单）：手续费显示 0.00，实际支付金额 = 充值金额。

四、各端改动

页面改动
后台 · 支付栏目新增/修改弹窗加「用户手续费」配置；列表加「用户手续费」列

后台 · 充值报表在「充值总额」后加「实际支付总额」「手续费总额」两列；总计行、导出同步

    需求说明 · 充值中心
    1. 每种类型展示一个支付方式，交互按类型区分：
      · 支付宝 / 微信 / USDT / 数字人民币 / 银联扫码 / 综合收款：输入金额或选固定金额
      · 虚拟币钱包：先选支付渠道，再选金额
      · 人工充值 / 银商充值：选银商跳转，不生成订单
      · 内嵌钱包：用钱包币兑换（不在支付栏目配置，不支持手续费）
    2. 收手续费的栏目，图标下方标注「手续费 2%」或「手续费 2元/笔」；「送 x%」角标不变。
    3. 选中收费栏目且金额合法时，金额下方实时显示：充值金额、手续费、实际支付、到账金额。手续费 = 固定金额，或充值金额 × 比例（四舍五入到分）。
    4. 虚拟币钱包类栏目也可能被配置手续费（系统不区分通道类型），配置后对该栏目下所有支付渠道生效，展示方式相同。可在后台给「虚拟币钱包」配置后切过来查看。
    5. 单笔上下限、固定金额按钮仍按充值金额判断。
    6. 按钮显示「立即支付 ¥实际支付金额」；不收费栏目保持「立即充值」。
    7. 收费栏目下方提示「使用钱包充值免手续费」，点「去使用」切到排在最前的内嵌钱包；没有内嵌钱包时不显示。
